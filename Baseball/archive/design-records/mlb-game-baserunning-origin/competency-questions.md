# Accepted baserunning-origin contract

The user answered **Yes** directly to approval of `hasBaserunningOriginBase`.
The accepted definition, evidence, source-independent shape and constraints
are preserved in [the review snapshot](baserunning-origin-review.md).

- Which base is the origin of this particular Baserunning Act? Link the act
  to its known first/second/third Base using the accepted new relation.
- Does this mean PA-start location or continued entitlement? No. It is scoped
  to the beginning of this act, with the persistent Role unchanged.
- Which runner and Game apply? The act and its runner resolution share the
  resolved Person and PA/Game context; the Base uses the same field context.
- What source permits the first mapping subset? An existing act/resolution,
  known runner, unambiguous row/event association and matching non-null start
  and originBase in 1B/2B/3B. Unknowns and disagreement stay unasserted.
- How can queries identify first/second/third? Reuse the accepted Code
  Identifier pattern; do not parse the Base IRI to obtain a metric position.
- Does a missing row establish unchanged state? No. Full boundary coverage,
  continuity and operative-resolution identity remain separate requirements.

SHACL must encode these constraints on linked acts, including source-record
aboutness, resolved-runner consistency and the explicit Base identifier.
