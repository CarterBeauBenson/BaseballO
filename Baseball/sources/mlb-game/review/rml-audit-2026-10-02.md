## Additional engineering defects fixed

1. **Input retirement race.** The award worker selected game 822748's input
   before acquiring the game lock. The history worker then promoted and retired
   that input at `2026-10-02T06:37:04.979469Z`; the award attempt failed two
   seconds later. Award, runner and compound repair wrappers now use the same
   existing resource lease as foul, defensive and history repairs, including
   their selection step. Their schedules and source-game locks remain in place.
2. **Incorrect retry identity.** The award worker treated an old per-game
   success or two failures as final even when the implementation or input bytes
   differed. Completion and retry limits now bind both the implementation and
   source hash. Terminal records retain the complete source witness.
3. **Transient inventory disappearance.** An input removed after directory
   enumeration could abort the whole award scan. The scan now skips that
   vanished entry and continues; changed bytes still receive a distinct hash.

The recorded 822748 attempt is resumed through the existing award worker and
the one-game [input-recovery manifest](../pipeline/award-input-recovery.json),
under the September 30 targeted reacquisition authorization. NiFi checks the
existing history cleanup receipt, fetches only that game's endpoint, preserves
the new response hash, and uses the unchanged W1/W2 maps and additive transaction.
Its owned response is retired after successful promotion, with a receipt;
interrupted cleanup resumes without mapping again. This is not a season fetch
or whole-game replacement.

Focused regressions cover exact-source retry limits, a retired inventory entry,
reacquisition provenance, interrupted cleanup, the existing resource lease and
F5/D2 proof compatibility. The three updated PowerShell wrappers parse. The
live RML and retry processors were RUNNING/VALID with no bulletins at the audit
snapshot. A healthy processor does not establish complete mapping coverage.

No new semantic gap was identified in the recorded cases examined here. Runtime
repair completion, remaining admission gaps and populated SQL results must still
be read from their respective NiFi owners; this audit does not certify that the
dashboard is fully populated.

## Second follow-up: execution and recovery defects

The next status snapshot contained 225 completed foul repairs and no failed
award repairs. Game 822748 promoted five missing triples in transaction
`df354a88fb03412b81f7146510e0de75`; its owned input has a completed retirement
receipt. The remaining 20 defensive failure records used the older
`781e5faa...` implementation, so they were not counted as new F5/D2 failures.
This snapshot does not establish that every defensive repair has retried.

This pass fixed engineering defects without changing the pinned RML, context
selector, ontology, source SHACL or semantic freeze:

- **Incorrect event lookup in the RML harness.** Its duplicate passed-ball and
  wild-pitch counter indexed `playEvents` by `details.playIndex`, although the
  context builder resolves that value against the event's `index`. A sparse
  index could fail before mapping. The harness now counts the selected
  `eventPlayId` values from the same context consumed by RML, including
  deduplication when several runners share a pitch. Uncaught-third-strike
  counting also uses its existing context flag. Existing output count checks
  remain in place; the duplicated source interpretation was removed.
- **Output replacement before detecting input change.** The final input-hash
  check now precedes copying the staged RDF to the output path. A changed
  input therefore leaves the previous RDF file intact.
- **Premature targeted completion.** The shared addition worker formerly
  returned success from a matching selection hash before validating the
  current promotion or executing the selected maps. It now checks the current
  selected triples against the live base. Empty RML output is a failure, not
  an `already-present` result. Missing triples still enter the existing scoped
  SHACL and additive transaction; no-op retries perform no graph write.
- **Inventory starvation.** Award and defensive inventories now include first
  promotion availability in their cache identity. An unchanged input inspected
  before promotion can become eligible later. Malformed JSON is recorded with
  its hash, and a file retired between enumeration and reading is skipped;
  either case allows later inputs to proceed within the existing scan bound.
- **Recovery provenance.** Reusing a completed addition requires the exact
  source witness, not just equivalent selected rows. An interrupted recovery
  can retire its owned input after confirming the prior promotion. A completed
  retirement receipt is left unchanged on later timer ticks, preserving its
  actual cleanup time.

Focused checks exercised sparse-index context against the installed RMLMapper,
shared-pitch deduplication, changed-input output preservation, empty and newly
missing deltas, promotion-dependent inventory retries, malformed/retired inputs,
and recovery idempotency. The updated PowerShell harness parses. The sparse
indexes are a synthetic regression derived from a retained sample, not a claim
that a newly observed MLB response contains that exact mutation. No checked-in
raw response was changed, no full-game mapping was run, and no new execution
gate or processor was added.
